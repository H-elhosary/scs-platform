## 1. متطلبات الأمان وتصنيف البيانات (Data Classification & Protection)

لضمان أقصى حماية لبيانات العيادات والمرضى الحساسة، يتم تصنيف البيانات وتحديد طريقة التعامل معها برمجياً:

### 1.1 تصنيف البيانات (Data Classification Matrix)

| فئة البيانات | أمثلة عليها | مستوى الحساسية | طريقة الحماية والتخزين |
|--------------|-------------|----------------|------------------------|
| **بيانات الهوية للمرضى (PII)** | الاسم، رقم الهاتف، الرقم القومي، البريد | 🔴 مرتفع جداً | تشفير AES-256 عند الحفظ + إخفاء جزئي في الواجهات العامة (Masking) |
| **البيانات الطبية (EMR)** | التشخيص، علامات الفحص السريري، الروشتات، الحساسيات | 🔴 مرتفع جداً | تشفير AES-256 عند الحفظ (At Rest) + فصل منطقي صارم لكل مستأجر |
| **الملفات والصور الطبية** | صور قبل/بعد، الأشعة والتحاليل، روشتات PDF | 🔴 مرتفع جداً | روابط مؤقتة مشفرة (Presigned URLs) ذات صلاحية تنتهي خلال 15 دقيقة |
| **سجلات العمليات (Audit Logs)** | حركات المستخدمين، أوقات القراءة والكتابة | 🟡 متوسط | حفظ في جدول مقسم (Partitioned) غير قابل للتعديل أو الحذف نهائياً |
| **بيانات العيادات** | أسماء الخدمات، ساعات العمل، الأسعار | 🟢 عادي | حماية عبر RLS للـ Multi-tenancy |

## 2. آليات التشفير وإدارة المفاتيح (Encryption & KMS)

### 2.1 التشفير أثناء النقل (In-Transit Encryption)
- **بروتوكول الشبكة:** إجبار استخدام **TLS 1.3** على جميع الاتصالات (HTTPS & WSS).
- **الشهادات:** تجديد تلقائي لشهادات SSL/TLS عبر **Let's Encrypt** كل 60 يوماً.
- **الحماية:** تفعيل **HTTP Strict Transport Security (HSTS)** لمنع الاتصالات غير الآمنة.

### 2.2 التشفير أثناء الحفظ (At-Rest Encryption)
- **مستوى نظام التشغيل وسيرفر قاعدة البيانات:** تشفير كامل لقرص البيانات الصلب (Full Disk Encryption) باستخدام **AES-256-XTS**.
- **مستوى التطبيق وقاعدة البيانات (Application-Level Encryption):**
  يتم تشفير الحقول الحساسة قبل تخزينها في PostgreSQL باستخدام خوارزمية **AES-256-GCM** بالاستعانة بمكتبة `pgcrypto` أو تشفيرها في كود الـ Node.js Backend.
  - **مفاتيح التشفير:** يتم توليد مفتاح تشفير فريد لكل عيادة (`Tenant_Encryption_Key`).
  - **حفظ المفاتيح:** تحفظ المفاتيح وتدار خارج قاعدة البيانات في **Key Management Service (KMS)** مثل (AWS KMS / HashiCorp Vault). السيرفر يسترجع المفتاح مؤقتاً في الـ Memory لفك التشفير عند الحاجة.

```sql
-- مثال توضيحي لفك تشفير اسم المريض برمجياً داخل الاستعلام
SELECT pgp_sym_decrypt(full_name_encrypted, current_setting('app.tenant_key')) AS full_name 
FROM patients 
WHERE tenant_id = 'clinic_uuid';
```

## 3. الامتثال للمعايير الصحية وأمن المعلومات (Compliance Standards)

### 3.1 معايير حماية البيانات الطبية (HIPAA & GDPR Compliance Guidelines)
بما أن النظام يتعامل مع سجلات طبية، يجب الامتثال للمبادئ التالية:
1. **حق النسيان (Right to be Forgotten):**
   - يحق للمريض طلب حذف بياناته. يتم تطبيق هذا برمجياً بحذف مفتاح التشفير الخاص ببيانات هذا المريض بالتحديد من قاعدة البيانات، مما يجعل قراءة بياناته القديمة مستحيلة للأبد (Crypto-Shredding) بالإضافة للـ Soft Delete.
2. **الحد الأدنى من الوصول (Principle of Least Privilege):**
   - السكرتير لا يمكنه تحت أي ظرف الوصول لجدول الـ SOAP Notes أو فك تشفير حقول التشخيص والخطة العلاجية. الصلاحية محصورة للطبيب المعالج فقط.
3. **فترة انتهاء الجلسة التلقائية (Auto Session Timeout):**
   - لوحة تحكم الطبيب والسكرتير تغلق تلقائياً وتطلب إعادة إدخال كلمة المرور إذا لم يتم استشعار أي حركة (Mouse move / Keyboard press) لمدة 15 دقيقة متواصلة.

## 5. سجل العمليات غير القابل للتعديل (Immutable Audit Trail)

لحماية النظام من التلاعب الداخلي أو تسريب البيانات، يقوم النظام بتوثيق كل حركة:

### 5.1 العمليات المراقبة إجبارياً (Audited Events)
يتم تسجيل العمليات التالية تلقائياً في جدول `audit_logs`:
- محاولات الدخول (الناجحة والفاشلة مع الـ IP والمتصفح).
- عمليات عرض السجل الطبي للمريض (لإثبات من قام بقراءة التشخيص ومتى).
- عمليات تعديل الأسعار أو إلغاء الفواتير والحجوزات.
- عمليات تغيير صلاحيات الموظفين.
- عمليات تصدير البيانات (Excel/PDF export).

### 5.2 حماية سجل العمليات من التعديل (Immutability Architecture)
- يتم تفعيل خيار **Append-Only** لجدول الـ Audit Logs على مستوى قاعدة البيانات.
- يتم تجريد مستخدم الـ API الخاص بالتطبيق (Database Application User) من صلاحيات الـ `UPDATE` والـ `DELETE` والـ `TRUNCATE` للجدول، ويمنح فقط صلاحيات الـ `INSERT` والـ `SELECT`.
- يتم عمل نسخ احتياطي مشفر وآنفي (Real-time Replication) لسجلات الأمان إلى سيرفر منفصل تماماً وبعيد عن متناول مدراء قاعدة البيانات الأساسيين.
- يتم إطلاق تنبيه أمني أحمر فوراً (Security Alert) لصاحب المنصة إذا تم تسجيل أي محاولة تعديل هيكلية على هذا الجدول.
