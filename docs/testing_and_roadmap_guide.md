# 🗺️ دليل خطة التطوير وتشغيل خادم الاختبار التفاعلي (Swagger UI)

يحتوي هذا المستند على التفاصيل الشاملة لخطة التطوير والوحدات البرمجية (Modules)، بالإضافة إلى إرشادات تفصيلية لكيفية تشغيل خادم الاختبار المحاكي (Mock API Server) واستخدام واجهة **Swagger UI** لتجربة جميع الروابط.

---

## 1. خطة التطوير وتقسيم الموديولات (Phased Development Plan)

تم تقسيم عملية تطوير **منصة عيادتي الذكية (Smart Clinic OS)** إلى 4 مراحل متتالية لتسريع إطلاق النظام وضمان تكامل الخصائص بسلاسة:

### 📅 المرحلة 1: البنية الأساسية، الأمان وإدارة المنصة (Platform Infrastructure & Administration)
- **الموديول الأول: عزل المستأجرين (Multi-Tenant Isolation Module):**
  - تهيئة قاعدة البيانات PostgreSQL وتفعيل سياسة عزل البيانات الصارمة (Row-Level Security) لضمان فصل بيانات كل عيادة عبر `tenant_id`.
  - إعداد مخزن المفاتيح (Key Management Service) لتوليد مفاتيح تشفير AES-256 منفصلة لكل عيادة وتشفير السجلات الطبية للمرضى.
- **الموديول الثاني: لوحة تحكم مشغل المنصة (Platform Operations Console):**
  - نشر لوحة الأوبريشن بشكل خاص ومغلق (`https://www.SCS-ops.com`) خلف شبكة افتراضية داخلية (VPN) وتقييد عناوين الـ IP.
  - تمكين مشغل المنصة من إضافة العيادات وتخصيص باقات الاشتراكات وصلاحيات الميزات (`allow_multi_doctor`, `allow_insurance`, `allow_refunds`).
- **الموديول الثالث: إدارة هوية الموظفين (Access Control Module):**
  - تفعيل نظام الصلاحيات الديناميكي المبني على الأدوار (RBAC) لربط السكرتاريا بالصلاحيات الإدارية وحظر وصولهم للبيانات الطبية.
  - إجبار التحقق الثنائي (2FA) عبر كود OTP لحسابات الأدمن والعيادات.

### 📅 المرحلة 2: البوت الذكي والفرز الطبي وبوابة الدفع (Automated Patient Journey)
- **الموديول الرابع: محرك البوت متعدد القنوات (Multi-Channel Bot Engine):**
  - ربط قنوات التواصل للمرضى (بوابات Meta WhatsApp Business API وبوتات Telegram Bot API).
  - كتابة خوارزمية الفرز الطبي التلقائي (Triage Rule Engine) لتحديد الكلمات الحرجة وتنبيه حالات الطوارئ.
- **الموديول الخامس: الحجز الذكي وإدارة المهل (Real-time Slots & Race Conditions):**
  - قراءة المواعيد الشاغرة لحظياً ووضع قفل مؤقت (Redis Distributed Lock) لمنع تضارب الحجز المزدوج.
  - تهيئة عداد تنازلي لإلغاء الحجز المؤقت آلياً (Background Worker: `payment-timeout`) وتحرير الـ Slots في حال عدم الدفع.
- **الموديول السادس: بوابة الدفع الإلكتروني (Payment Gateway агрегатор):**
  - ربط بوابات الدفع الرسمية (Paymob للكروت والمحافظ الإلكترونية، وفوري للدفع عبر الأكشاك).

### 📅 المرحلة 3: لوحة تحكم العيادة والملف الطبي الرقمي (Dashboard Operations & EMR)
- **الموديول السابع: صندوق الوارد الموحد (Omnichannel Inbox & Manual Takeover):**
  - واجهة دردشة موحدة للسكرتاريا لاستقبال رسائل الواتساب والتليجرام، مع مفتاح لتعطيل البوت مؤقتاً لمدة ساعة للرد اليدوي.
- **الموديول الثامن: الملف الطبي والروشتة الإلكترونية (Dynamic EMR & E-Prescription):**
  - واجهة فحص SOAP للأطباء، وتكامل محرك البحث مع تصنيفات منظمة الصحة العالمية (WHO ICD-11).
  - توليد روشتات PDF مشفرة تحمل QR Code مع توقيع رقمي فريد للطبيب وإرسالها تلقائياً بالواتساب/التليجرام/البريد.
- **الموديول التاسع: شاشة الانتظار العامة (TV waiting screen):**
  - واجهة عامة متصلة بالـ WebSockets لإصدار نغمة تنبيه صوتية وتحديث أرقام الطابور تلقائياً.

### 📅 المرحلة 4: العمل دون اتصال ومحرك التسويق والتقارير (Offline-First & BI)
- **الموديول العاشر: العمل أوفلاين والمزامنة (Offline Sync Engine):**
  - تشغيل الواجهات كـ PWA وتخزين المواعيد في IndexedDB محلياً، وإرسال المزامنة (`POST /v1/sync`) عند عودة الإنترنت وحل النزاعات يدوياً.
- **الموديول الحادي عشر: محرك التسويق الذكي (Segmented Campaigns Engine):**
  - فلترة المرضى وبث الرسائل الجماعية الرسمية بفواصل زمنية عشوائية (2-5 ثوانٍ) لمنع حظر الرقم، وتفعيل ساعات الليل الهادئة.
- **الموديول الثاني عشر: التقارير والذكاء الاصطناعي التشغيلي (Financial & Operational BI):**
  - إرسال تقارير بريدية آلية للأطباء (يومية وأسبوعية)، ورسم بياني لمؤشرات الأداء.

## 2. كيفية تشغيل خادم الاختبار المحاكي (Testing & Running Instructions)

لتسهيل تجربة واجهات برمجة التطبيقات (APIs) والتأكد من مطابقة جميع التعديلات الأخيرة، تم بناء **خادم اختبار محاكي تفاعلي (Mock API Server)** مدمج به واجهة **Swagger UI**.

### 🛠️ متطلبات التشغيل الأساسية:
- يجب أن يكون خادم **Node.js** (إصدار 16 أو أحدث) مثبتاً على جهازك.

### 🚀 خطوات التشغيل والتهيئة:

1. **تثبيت المكونات البرمجية:**
   قم بفتح واجهة الأوامر (Terminal/CMD) في مجلد المشروع الرئيسي (`c:\Users\hmohamed\Downloads\SCS`) وتشغيل الأمر التالي لتثبيت المكتبات المطلوبة:
   ```bash
   npm install
   ```

2. **تشغيل الخادم المحاكي:**
   قم بتشغيل الخادم باستخدام الأمر التالي:
   ```bash
   npm start
   ```
   عند التشغيل بنجاح، ستظهر لك الرسالة التالية:
   ```text
   🚀 Smart Clinic OS Mock API Server is running on port 3000
   📖 Swagger API Documentation: http://localhost:3000/api-docs
   ```

3. **تصفح وتجربة الروابط عبر Swagger UI:**
   - افتح متصفح الإنترنت وتوجه إلى الرابط التالي:
     👉 [http://localhost:3000/api-docs](http://localhost:3000/api-docs)
   - ستظهر لك واجهة Swagger التفاعلية الأنيقة.
   - يمكنك الضغط على أي رابط (مثال: `GET /v1/settings/notifications` أو `POST /v1/sync`) ثم الضغط على **Try it out** وتعديل البيانات والضغط على **Execute** لتشاهد استجابة السيرفر الواقعية وحالة الـ HTTP Status.

## 3. تفاصيل الروابط المتاحة للاختبار في السيرفر (API Catalog):

| مسار الرابط (Endpoint) | نوع الطلب (HTTP Method) | الغرض والوظيفة |
|-----------------------|-------------------------|----------------|
| `/admin/v1/auth/login` | `POST` | تسجيل دخول المشغل (أدخل بريد `ops@SCS-ops.com` للتجربة) |
| `/admin/v1/auth/verify-2fa` | `POST` | التحقق من كود الـ 2FA (أدخل كود `123456` للتجربة) |
| `/admin/v1/tenants` | `POST` | إنشاء حساب عيادة وطبيب جديد (يعيد رابط التفعيل ونطاق العيادة) |
| `/admin/v1/tenants` | `GET` | عرض قائمة العيادات المسجلة وإحصائياتها (عرض معلومات باقة الاشتراك) |
| `/v1/staff` | `POST` | إضافة حساب سكرتير وتحديد صلاحياته الأساسية |
| `/v1/staff/{id}/permissions` | `PUT` | تحديث مصفوفة الصلاحيات الخاصة بالسكرتارية |
| `/v1/chats/{conversation_id}/toggle-bot` | `POST` | تفعيل وضع التدخل اليدوي وإيقاف البوت مؤقتاً لمدة ساعة |
| `/v1/appointments/{appointment_id}/consultation` | `POST` | حفظ ملف فحص SOAP وتوليد الروشتة PDF مشفرة مع الـ QR |
| `/v1/sync` | `POST` | محاكاة مزامنة طابور العمليات أوفلاين وفض النزاعات |
| `/v1/queue/call-next` | `POST` | محاكاة نداء المريض التالي وتحديث شاشة تلفزيون الانتظار |
| `/v1/settings/notifications` | `GET` | **[ميزة جديدة]** استرجاع تفضيلات إشعارات العيادة |
| `/v1/settings/notifications` | `PUT` | **[ميزة جديدة]** تحديث وتخصيص إشعارات العيادة (واتساب/بريد/SMS) |
| `/webhooks/whatsapp` | `GET` | التحقق من رمز Meta عند ربط خادم الواتساب لأول مرة |
| `/webhooks/telegram` | `POST` | استقبال رسائل التليجرام من المرضى ومعالجتها |
